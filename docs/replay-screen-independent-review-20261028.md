## Concrete preservation and measurement limits

1. **Final recent trajectories are not all complete episodes.** `replay_robot.py:92,115–118` saves a rolling deque of 50 vector steps. A 50-step window contains complete 64-environment episodes only when the current vector-step count is divisible by 50. Prespecified checkpoints do align; deadline-censored finals need not. Target's final 13,670 vector steps leave remainder 20; joint's 9,321 leave 21; split's 6,400 leave 0. Target/joint final windows therefore contain suffixes of one episode and prefixes of another, not 64 complete 50-step episodes. The file's own note correctly says “recent50 training steps,” while the scientific plan's promise to retain complete recent episodes is stronger than this implementation provides. Masks let an analyst identify fragments; they do not recover missing prefixes/suffixes. Use the existing **256,000-transition checkpoint** for a common complete-episode window, not a fabricated final Monte Carlo return. Even there, behavior changes during the training episode; it is not a frozen-policy rollout.

2. **Saved state is insufficient to reconstruct historical target-SAC targets or resume exactly.** `replay_robot.py:108–114` saves actor, online q1/q2 parameters/buffers, log-alpha and Torch RNG states. It omits `target1/target2`, Adam states, full replay, environment state and NumPy/Python RNG states. Target networks evolve by Polyak averaging; current online weights alone cannot recover them. Recomputed online-Q targets would be a counterfactual, not the original target-SAC bootstrap. Existing logged target means/maxima are genuine historical aggregates. The NPZ is useful diagnostic state, not a full restart checkpoint. This limits retrospective explanations; it does not change the exported actor or score.

3. **Logged metrics are the last learner call, not block or trajectory averages.** `replay_robot.py:155–169` overwrites `stats` during each update block and logs the final call every 5,120 transitions. Actor/temperature/log-probability fields appear only when that last call lands on the three-update actor cadence. Missing fields do not mean no actor update occurred. Logged alpha is captured before that call's possible alpha step. `Learner.diagnostics()` is not called by the robot loop, so its policy-Q diagnostics cannot be assumed present in these logs.

4. **The diagnostic helper is not RNG-neutral.** `Learner.diagnostics()` restores critic training flags and leaves normalization buffers unchanged, but `actor.sample()` advances Torch RNG. It also deliberately increments forward-work counters. This did not affect these runs because the robot never invokes it. A future read-only measurement should use clones plus saved/restored RNG, not call it on a continuing live learner and assume complete state immutability.

## Normalization: intended contrast and unresolved bridge to actor learning

During critic fitting, both normalized methods concatenate current replay and successor/current-policy rows. Joint uses pooled moments; split normalizes the two halves separately. Both update pooled EMA once per layer/critic update, with old-stat weight .99. The target is detached **after** the shared forward, so successor inputs can still influence current prediction gradients through pooled moments. This matches the intended experiment; putting the entire successor branch under no-grad would instead change it.

During actor optimization the critics use `eval()` and stored running statistics. The actor therefore follows a different critic function from the training-mode batch-normalized critic used in the Bellman fit. The EMA was computed with pre-optimizer activations; the actor then sees post-optimizer weights with those running statistics. This is a **real measurement question**, not a discovered accidental mode toggle: the prior review explicitly chose this author-inspired actor mode. Replacing it with training mode would be another intervention, not a harmless repair.

All recorded normalizers remain below 100,000 updates (joint 36,968; split 25,283), so the robot learned entirely in warmup BN. It provides no evidence about postwarm BRN correction quality. The shared EMA rule controls cadence, not numerical buffer equality: deeper activations already differ between joint/split, so deeper running moments can legitimately diverge. Their source distinction includes gradient coupling and subsequent policy/data feedback, not simply one fixed shift in target values.

The [LQR report](research-window-replay-value-20261028.md) establishes the split final-centered-layer training mean restriction and its failure in that specific fixed-policy toy. It also reports that the conventional target critic has lower action-derivative RMSE than joint in all three toy seeds. The robot has twin-min targets, entropy, learned actions and a different discount/data distribution. Do not transfer the toy's scalar fixed-point bias or “true target accuracy” numerically to this robot. The algebraic per-head centering restriction remains relevant; the true robot current/next value gap has not been measured.

## Cheapest discriminating diagnostic, if separately reviewed

Use the existing common 256k snapshots and their aligned recent training windows; acquire no new simulator data and make no scorer calls. On frozen clones with identical fixed row indices and declared successor-action noise, compare the **same critic parameters** in batch-training versus untouched-running-stat views. Record per-head current/next means, view discrepancy, running-versus-batch standardized moment gaps, and running-view actor action-gradient norms. Measure the running view from a separate untouched clone **before** any training-mode forward can change buffers; preserve RNG and count every forward/backward row. Use actual archived behavior transitions and identify the policy action used; do not call this a historical Bellman-target reconstruction or a true-Q oracle.

This tests whether an extreme training/inference bridge is present in the normalized critics that the scalar fit loss misses. A small gap weakens that explanation. A large gap motivates a narrow calibration hypothesis, but cannot alone establish wrong action gradients or explain target-SAC's failure, since that control has no BN view difference. Keep the root's entropy/coverage/stage analysis separate. No learner rerun, normalization repair, new algorithm, broad sweep or extra evaluation follows automatically from this recommendation.

**Artifact question:** a scoring/export artifact is possible in principle, but the inspected source and aggregate metadata provide no concrete evidence for one. Deterministic export algebra/parity, completed 128-episode reports without execution failures, and zero recorded training terminal successes all point toward genuine absence of stacking competence in these saved policies. The unresolved explanations are learning/coverage/objective issues and the normalization bridge, not a demonstrated invalid evaluator. Do not relabel the zero scores as an infrastructure failure.
