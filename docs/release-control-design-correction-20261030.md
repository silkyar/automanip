# Release diagnostic: validity failure and corrected design

The first diagnostic did not produce a valid comparison. It stopped with an incomplete target-intervention batch and a command-budget guard; the frozen evaluator had sanitized the underlying rollout error to `ValueError`. The failed batch's detailed prefix was not retained, so the exact root cause cannot be proved. The fully retained preceding target batch had bit-identical pre-intervention observations. Partial scores are not a scientific result.

Repeating this design was an avoidable mistake: the earlier [lift probe](lift-control-results-20261029.md) had already demonstrated divergence after identical resets and actions, with hidden solver state unresolved. Exact replay was therefore an unsupported assumption. The second worker was cancelled after its peer failed. All three recent Modal apps were read back stopped with zero tasks.

Actual confirmed work was71,104 transitions. One additional64-transition call was reserved without a completed journal record when cancellation occurred; its physical completion is unknown. We retain that uncertainty rather than report an exact total. There were zero optimizer calls. Thirty-five remote files,25,197,486bytes, were archived with hashes and source provenance. [Failure account](../cumulative/results/release-control-failure-20261030.json).

The replacement [registered diagnostic](../cumulative/experiments/randomized-release-probe-v1.json) assigns16lanes to each of four intervention groups before each64lane rollout, independently of geometry and outcomes. Each of two fixed failed policies receives32such batches, yielding512assigned episodes per group per policy. All interventions deliver exactly five opening commands; target-based groups use a late fallback. The four arms isolate unchanged behavior, fixed timing, geometric timing, and added zero arm motion. All assigned episodes count.

This design estimates randomized group effects and requires no counterfactual state replay. Analysis resamples whole vector batches, uses four registered98.75%intervals, and conditions on the two fixed policies. It does not establish effects across training seeds. Numerical coupling among scenes in the GPU simulator remains a possible limitation; results concern this pinned simulator configuration. New work is capped at204,800transitions and zero updates. Manual controller gains will never replace learned-policy benchmark scores.
